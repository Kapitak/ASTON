## О задании ![Java CI with Maven](https://github.com/Kapitak/Clue/actions/workflows/maven.yml/badge.svg)

Необходимо написать приложение, реализующее **алгоритм сортировки** выбранного класса. 

### Требования к репозиторию

- Количество веток с кодом должно соответствовать количеству участников (**минимум** — по одной на каждого).
- Все ветки в итоге должны быть **смерджены** в ветку `main`.

```bash
# Пример работы с ветками
git checkout -b student_name/feature
git add .
git commit -m "<PREFIX>: <MESSSAGE>"
git push origin student_name/feature

# После завершения работы — слияние в main
git checkout main
git merge student_name/feature
git push origin main
```

**Префикс <PREFIX> в commit:**
- **feat**: —  новая функциональность;
- **fix**: — исправление бага;
- **docs**: — только документация;
- **refactor**: — рефакторинг без смены поведения;
- **test**: — тесты;
- **chore**: — служебное (обновление зависимостей, настройка CI).
---

## Функциональные требования

- Код и архитектура должны соответствовать **конвенциям языка Java**.
- Программа работает **в цикле** — выход только по соответствующему выбору пользователя.
- Пользователь может выбирать:
  - вариант заполнения массива данных (**из файла**, **рандом**, **вручную**);
  - длину массива.
- Использовать паттерн **«Стратегия»**.
- Сортировать **кастомные классы** — класс должен иметь реализованный паттерн **«Строитель» (Builder)**.
- Для вводимых данных (в т.ч. из файла) должна производиться **валидация**.
- Сортировка должна быть базово реализована **по всем 3 полям**.

| 1 | Автобус | Номер, Модель, Пробег |

## Дополнительные задания

### + Доп. задание 1 — «Чётная сортировка»
Дополнительно к основным сортировкам реализовать эти же алгоритмы так, чтобы объекты сортировались по **числовому полю**:
- объекты с **чётными** значениями поля — в **натуральном порядке**;
- объекты с **нечётными** значениями — **остаются на исходных позициях**.

### + Доп. задание 2 — Запись в файл
Функционал для записи отсортированных коллекций / найденных значений в файл в **режиме добавления** данных.

### + Доп. задание 3 — Стримы
Заполнение коллекций должно осуществляться посредством **стримов**.

**3\*** — коллекции для заполнения должны быть **кастомными**.

### + Доп. задание 4 — Многопоточность
Многопоточный метод, подсчитывающий количество вхождений элемента `N` в коллекцию и выводящий результат в консоль.

---

## Общие требования

- Все классы должны базово реализовывать сортировку **по всем 3 полям**.
- Для кастомной сортировки разрешено использовать **компаратор**.
- **Запрещено** применять готовые реализации сортировки, поиска и паттернов.
- В программе должны быть реализованы **тесты** к написанному коду:
  - классические тестовые библиотеки использовать **не обязательно** (но можно);
  - достаточно **просто тестов в отдельных классах**, реализованных руками.
